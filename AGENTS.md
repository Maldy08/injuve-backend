## Project Overview

**SIRH** (Sistema Integral de Recursos Humanos) — Node.js/Express REST API for payroll management at INJUVE (Instituto de la Juventud del Estado de Baja California). Manages employee data, generates PDF pay stubs via jsreport, ingests CSV data, and sends emails. All data lives in MongoDB.

## Commands

```bash
# Start server (defaults to port 3001)
npm start

# Run full stack locally (MongoDB + Mongo-Express at localhost:8081)
docker-compose up

# No test suite or linter is configured in this project
```

## Architecture

All routes are prefixed with `/api/backend`. `server.js` initializes jsreport and MongoDB before Express starts listening.

```
server.js              → entry point: mounts routes, inits jsreport + MongoDB
routes/                → route definitions (thin, delegate to controllers)
controllers/           → business logic
helpers/
  mongo.helper.js      → MongoDB singleton (conectarMongo / getDb)
  jsreport.helper.js   → jsreport singleton (initJsReport)
  get-datos-nomina.js  → assembles full payroll data object for PDF rendering
  tablas-conversion-camposnumericos.js → numeric field mapping per CSV collection
templates/             → Handlebars HTML templates rendered to PDF by jsreport
middleware/            → JWT auth + API key auth
swagger.js             → OpenAPI 3.0 definition; served at /api-docs
```

## Auth Model

Three tiers:

1. **Public** — `/api/backend/auth` (no token required)
2. **API key OR JWT** — `/api/backend/upload` — agents send `x-api-key` header matching `API_KEY_AGENTE`; humans use JWT
3. **JWT required** — all other routes; middleware applied globally

JWT payload from `auth.login`: `{ EMPLEADO, RFC, NOMBRE }` | from `auth.loginMobile`: `{ userId, email }`  
Token expiry: 4 hours. Verified against `SECRET_KEY`.

## MongoDB Collections & Data Model

The `tipo` parameter distinguishes employee categories throughout the entire codebase:

| `tipo` | Employee table | Payroll table |
|--------|----------------|---------------|
| `1`    | `mnom01`       | `mnom12`      |
| `2`    | `mnom01h`      | `mnom12h`     |

Supporting collections: `mnom03` (categories/puestos), `mnom04` (departments), `accesos` (login access control), `sueldoprestacionesbase`, `sueldoprestacionesconf`, `usuarios`, `niveles`, `nivelesconfianza`.

MongoDB is accessed via the **native driver** (no Mongoose). Always use `getDb()` from `helpers/mongo.helper.js` — it throws if called before `conectarMongo()` completes.

## PERCDESC Classification

Used in every payroll calculation to classify line items:

- `1–12` → percepciones (tipo 1) / `1–23` → percepciones (tipo 2)
- `13–499` → prestaciones (tipo 1) / `24–499` → prestaciones (tipo 2)
- `≥500` → deducciones (both types), **except code `570`**
- Codes `40` and `60` are always percepciones regardless of range

## PDF Generation

PDFs are generated by jsreport using the `chrome-pdf` recipe with Handlebars templates:
- `templates/nomina.html` — tipo 1 (base employees)
- `templates/nomina-asim.html` — tipo 2 (confianza/honorary)

On Windows, jsreport auto-creates `jsreport-temp/` and passes `--allow-file-access-from-files` to Chromium. The jsreport Express extension is always disabled.

## CSV Upload Convention

`POST /api/backend/upload/:coleccion` replaces MongoDB data from a CSV file:
- `mnom12` / `mnom12h`: replaces only the matching `PERIODO`, not the entire collection
- All other collections: full replace (`deleteMany({})` then `insertMany`)
- BOM (`\uFEFF`) is stripped from the first CSV field automatically
- When uploading `mnom01` or `mnom01h`, `accesos` entries are auto-created for new RFCs
- Add new collections with numeric fields to `helpers/tablas-conversion-camposnumericos.js`

## Environment Variables

Required in `.env` (see `.env.example`):

```
PORT=3001
MONGO_URI=mongodb://...
DB_NAME=injuve
SECRET_KEY=...
EMAIL_USER=...
EMAIL_PASS=...
API_KEY_AGENTE=...
```

Default Docker credentials: MongoDB app user `sirh_user`/`sirh_password`, Mongo-Express `admin`/`admin`.

## Deployment
